# STEM-проєкт: аналіз та обробка зображень класичними методами

Командний STEM-проєкт (3 особи) з теми «Аналіз та обробка зображень за
допомогою класичних методів фільтрації, сегментації та аналізу текстур».
Усі методи реалізовані вручну — без бібліотек комп'ютерного зору/ML для
самих алгоритмів (бібліотеки дозволені лише для вводу/виводу зображень).

## Статус

**Чернетка.** Технічне завдання ([TZ.md](TZ.md)) потребує узгодження з
викладачем, перш ніж починати реалізацію пайплайнів — див. «Порядок дій»
нижче. Домен вибірки (обличчя/біометрія, датасет LFW) і розподіл категорій
між учасниками — попередні пропозиції, їх можна змінити до затвердження ТЗ.

## Структура репозиторію

```
TZ.md                   Технічне завдання (тема, вибірка, методи по людях,
                         рівень складності, порогові метрики) — для викладача
META-USAGE.md            Декларація використання ШІ-інструментів (обов'язково,
                         якщо хтось із команди користувався ними)
requirements.txt         Залежності (Pillow, numpy, pyyaml, pytest)
config/
  pipelines.yaml          Реєстр пайплайнів і їх параметрів
common/                  СПІЛЬНА інфраструктура команди (блок C)
  io.py                   Завантаження/збереження зображень (бібліотека лише тут)
  metrics.py              PSNR / MSE / SSIM — реалізовані вручну
  pipeline_runner.py       Виконує обраний пайплайн за конфігом
  cli.py                   Командний рядок: --member --pipeline --image
  compare.py               Зведене порівняння всіх пайплайнів команди
src/
  member1/pipeline1/ ...  Особиста зона кожного учасника (2 пайплайни кожен)
  member1/pipeline2/
  member2/pipeline1/
  member2/pipeline2/
  member3/pipeline1/
  member3/pipeline2/
data/
  README.md               Звідки вибірка, як завантажити
  samples/                 Невелика трекована підмножина для демо/тестів
tests/
  common/test_metrics.py   Готові тести метрик
  member1/ ...             Шаблони тестів під кожен пайплайн (заповнюють автори)
docs/
  related_work.md          Огляд суміжних робіт (≥5, потрібно для критерію C5)
results/                   Генерується програмою (у .gitignore)
report/                   Фінальний звіт і асети до нього
```

## Хто що робить

- **`common/`** — спільна інфраструктура (блок C, 30% / 12 балів, однакова
  оцінка для всіх трьох). Будь-хто з команди може почати, інші — рев'ювлять
  через PR.
- **`src/<member>/pipelineN/`** — особиста зона кожного (блоки A, B, D, E,
  70% / 28 балів персонально). Це код, який кожен має пояснити і
  модифікувати наживо на захисті — тому писати (або хоча б повністю
  розуміти) його має сама людина, навіть якщо користується ШІ-агентом як
  помічником (задекларувавши це в [META-USAGE.md](META-USAGE.md)).

Розподіл категорій методів по людях — у [TZ.md](TZ.md).

## Порядок дій

1. Замінити `member1`/`member2`/`member3` на реальні імена чи GitHub-логіни
   (у `src/`, `tests/`, `TZ.md`) — це потрібно для «персоналізованої історії
   комітів» (критерій A1).
2. Погодити вибірку зображень і домен (зараз чернетка — обличчя/LFW).
3. Узгодити `TZ.md` з викладачем **до** початку реалізації пайплайнів.
4. Створити спільний GitHub-репозиторій, дати доступ викладачу, додати
   `url` у `repos.yaml` University-репо.
5. Кожен працює у своїй гілці `feature/<ім'я>-pipelines`, мерджить у `main`
   через PR. Спільний `common/` — теж через PR із рев'ю від когось іншого.
6. Кожен реалізує свої 2 пайплайни + тести, потім запускає `compare.py` для
   зведеного порівняння.
7. Написати звіт (`report/`), підготуватися до захисту (кожен пояснює
   власний код).

## Запуск (після того, як пайплайни реалізовані)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# один пайплайн на одному зображенні:
python common/cli.py --member member1 --pipeline pipeline1 --image data/samples/sample_01.jpg

# повний прогін усіх пайплайнів на всій вибірці + метрики:
python common/compare.py
```
