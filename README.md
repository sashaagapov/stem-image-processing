# STEM-проєкт: аналіз супутникових знімків класичними методами

Командний STEM-проєкт (3 особи) з теми «Аналіз та обробка супутникових/
аерознімків земної поверхні за допомогою класичних методів фільтрації,
сегментації, контурного аналізу та аналізу текстур». Усі методи
реалізовані вручну — без бібліотек комп'ютерного зору/ML для самих
алгоритмів (бібліотеки дозволені лише для вводу/виводу зображень).

## Статус

**Реалізовано.** Спільна інфраструктура (`common/`) і всі 6 алгоритмічних
пайплайнів (`src/member*/pipeline*/`) готові й покриті тестами (61 тест).
Вибірка — 100 зображень (6 класів UC Merced), повний прогін усіх
пайплайнів на ній — у `results/metrics_summary.csv`, аналіз — у
[`report/assets/pipeline_comparison.md`](report/assets/pipeline_comparison.md),
повний звіт — у [`report/report.docx`](report/report.docx). Технічне
завдання ([TZ.md](TZ.md)) — чернетка, що потребує узгодження з
викладачем за умовами методички; домен вибірки й розподіл категорій між
учасниками — там само.

## Структура репозиторію

```
TZ.md                   Технічне завдання (тема, вибірка, методи по людях,
                         рівень складності, порогові метрики) — для викладача
requirements.txt         Залежності (Pillow, numpy, pyyaml, pytest)
config/
  pipelines.yaml          Реєстр пайплайнів і їх параметрів
common/                  СПІЛЬНА інфраструктура команди (блок C)
  io.py                   Завантаження/збереження зображень (бібліотека лише тут)
  metrics.py              PSNR / MSE / SSIM — реалізовані вручну
  pipeline_runner.py       Виконує обраний пайплайн за конфігом
  cli.py                   Командний рядок: --member --pipeline --image
  menu.py                  Консольне меню: усі 6 пайплайнів, картинка «до/після»
  compare.py               Зведене порівняння всіх пайплайнів команди
src/
  member1/pipeline1/ ...  Особиста зона кожного учасника (2 пайплайни кожен)
  member1/pipeline2/
  member2/pipeline1/
  member2/pipeline2/
  member3/pipeline1/
  member3/pipeline2/
data/
  README.md               Звідки вибірка, як завантажити
  samples/                 Невелика трекована підмножина для демо/тестів
tests/
  common/test_metrics.py   Готові тести метрик
  member1/ ...             Шаблони тестів під кожен пайплайн (заповнюють автори)
docs/
  related_work.md          Огляд суміжних робіт (≥5, потрібно для критерію C5)
results/                   Генерується програмою (у .gitignore)
report/                   Фінальний звіт і асети до нього
```

## Хто що робить

- **`common/`** — спільна інфраструктура (блок C, 30% / 12 балів, однакова
  оцінка для всіх трьох). Будь-хто з команди може почати, інші — рев'ювлять
  через PR.
- **`src/<member>/pipelineN/`** — особиста зона кожного (блоки A, B, D, E,
  70% / 28 балів персонально). Це код, який кожен має пояснити і
  модифікувати наживо на захисті — тому писати (або хоча б повністю
  розуміти) його має сама людина, навіть якщо користується ШІ-агентом як
  помічником (повідомивши про це викладачці напряму).

Розподіл категорій методів по людях — у [TZ.md](TZ.md).

## Як це було зроблено

1. GitHub-логіни учасників зафіксовано в [TZ.md](TZ.md); самі
   ідентифікатори `member1`/`member2`/`member3` навмисно лишені як
   технічні (їх використовує код і конфіг) — див. примітку в TZ.md.
2. Вибірку (UC Merced Land Use, 100 знімків із 6 класів) завантажено в
   `data/samples/` — деталі в [`data/README.md`](data/README.md).
3. Кожен працював у своїй гілці `feature/<ім'я>-pipelines`, мерджив у
   `main` через PR. Спільний `common/` — теж через PR із рев'ю.
4. Кожен реалізував свої 2 пайплайни + тести, потім команда прогнала
   `compare.py` для зведеного порівняння.
5. Звіт — у [`report/report.docx`](report/report.docx); ТЗ ще потребує
   фінального узгодження з викладачем перед захистом.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# один пайплайн на одному зображенні:
python -m common.cli --member member1 --pipeline pipeline1 --image data/samples/agricultural_01.jpg

# повний прогін усіх пайплайнів на всій вибірці + метрики:
python -m common.compare
```

### Консольне меню (Windows, Visual Studio)

Один раз підготувати проєкт (у терміналі, з кореня репозиторію):

```bash
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск у Visual Studio: **Файл → Відкрити → Папка** → корінь репозиторію;
у Solution Explorer правою кнопкою на `common/menu.py` → **Set as Startup Item** → **▶ Пуск**.
Без Visual Studio: `.\.venv\Scripts\python.exe common\menu.py`.

У меню: номер пайплайна (1–6) → шлях до знімка або ім'я з `data/samples`
(Enter — `river_02.jpg`) → програма виводить стадії й метрики, зберігає результати
в `results/<member>/<pipeline>/<знімок>/` і відкриває `comparison.png` (оригінал і всі
стадії в один ряд). `T` — запустити всі тести, `0` — вихід. Якщо меню запущено не тим
Python, воно саме перезапускається через `.venv`.
